BIG-IP 設備本身的緩解

BIG-IP 的管理介面也使用 PHP，同樣受 php2shell 影響。F5 目前還沒有修正版，請先完成下面 2 項緩解。這和保護後端網站的 WAF 設定是兩件不同的事。

攻擊條件F5 說明，管理介面的攻擊需要由已登入的使用者發動。所以除了緩解 1，最重要的是限制誰能連到管理介面（緩解 2）。

緩解 1　調整 BIG-IP 上的 PHP 設定

F5 建議套用 PHP 官方提供的設定緩解。請先在測試環境確認，再套用到正式設備。

1

以 root 登入 BIG-IP 的 bash（advanced shell）

2

建立 /etc/php.ini.d/K000163821.ini

cat > /etc/php.ini.d/K000163821.ini <<'EOF'
; The configuration mitigations recommended by PHP for CVE-2026-109618 and CVE-2026-109619
; These will NOT survive an upgrade of BIG-IP TMOS.
memory_limit = -1
post_max_size = 8M
upload_max_filesize = 7M
session.upload_progress.enabled = 0
EOF
3

重新啟動 Apache

bigstart restart httpd
# only when APM or SSLO is provisioned:
bigstart restart httpd_sam

重新啟動期間 GUI 會短暫無法使用，請在維護時段執行。沒有啟用 APM／SSLO 的設備，httpd_sam 會顯示「Not provisioned」，不需要重啟。

4

確認 PHP 已讀到新檔案

php -i | grep -E "Additional .ini|memory_limit|post_max_size|upload_max_filesize|session.upload_progress.enabled"

「Additional .ini files parsed」應包含 /etc/php.ini.d/K000163821.ini，4 個設定值應與上面的檔案相同。

參考：在 BIG-IP 17.5.1.8 上，套用前的值如下（以上述指令唯讀查得）：

設定17.5.1.8 原本的值F5 建議的值
memory_limit128M-1
post_max_size300M8M
upload_max_filesize300M7M
session.upload_progress.enabledOn0（Off）
注意 多 blade 的系統，每個 blade 都要做。升級 TMOS 後這個檔案不會保留，升級後要重新建立。

緩解 2　限制管理介面的存取

F5 說明，只要使用者還能登入管理介面，就沒有可行的緩解方式。所以要移除不完全可信任的使用者，並讓管理介面只開放給可信任的網段與設備。

2-1　管理埠：只允許可信任的來源 IP（K13309）

預設允許所有來源 IP（allow { All }）。用 tmsh 改成只允許管理網段：

tmsh list /sys httpd allow
tmsh modify /sys httpd allow replace-all-with { 192.0.2.0/255.255.255.0 }
tmsh save /sys config

範例中的 192.0.2.0/24 請換成實際的管理網段，可列多個。

小心不要把自己鎖在外面清單設錯時，GUI 會無法連線。請先從清單內的位址再開一個 SSH 連線備用。HA 對端設備、BIG-IQ、DCD 的位址也要加入清單（參考 K000160309）。
舊版本的限制BIG-IP 17.1.3.1、17.5.1.4 之前的版本，這份清單不會限制 port 443 上的 iControl REST。

2-2　Self IP：關閉 GUI 的存取（K17333）

Self IP 的 Port Lockdown 若設為 Allow Default，預設清單已包含 TCP 443（HTTPS），也就是可以從 Self IP 連到管理介面。請改成不含 TCP 443 的設定：

情況建議的 Port Lockdown
單機，或 HA 使用 hardwired failoverAllow None
HA 使用 network failoverAllow Custom，只開 UDP 1026
任何情況不要使用 Allow All
GUI 路徑Network ›› Self IPs ›› （Self IP 名稱）›› Port Lockdown ›› Update
tmsh list /net self
# no access to the self IP (ICMP is always allowed)
tmsh modify /net self <self_ip_name> allow-service none
# HA network failover only
tmsh modify /net self <self_ip_name> allow-service replace-all-with { udp:1026 }
tmsh save /sys config
  • HA 設備之間的 config sync（TCP 4353）與 mirroring 埠，不受 Port Lockdown 限制，會繼續運作。
  • 如果 DNS（GTM）的 iQuery 不是走 config sync 位址，要另外開放 TCP 4353。
  • 如果必須在 Self IP 開放 TCP 443，可用 BIG-IP 的 packet filter 限制來源網段（K13383）。
變更前確認Port Lockdown 會影響 Self IP 上的所有服務（例如 SNMP、SSH、DNS），HA 設定也可能受影響。請先確認這些服務是否經由 Self IP 使用（參考 K46122561）。

2-3　管理帳號

移除不是完全可信任的管理帳號，或降低其權限。管理介面的攻擊需要已登入的帳號。
