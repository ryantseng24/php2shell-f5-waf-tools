BIG-IP 設備本身：升級與緩解

BIG-IP 的管理介面與 APM 的 Access profile 也使用 PHP，同樣受 php2shell 影響。F5 已發布修正版，所有受影響的設備都要升級。升級的急迫程度，依設備是否使用 APM 而不同。這和保護後端網站的 WAF 設定是兩件不同的事。

升級的優先順序

請依設備的情況，決定升級的時程。

設備情況原因建議
第 1 類
有啟用 APM 或 SSLO		Access profile 的攻擊不需要登入。能連到 APM 服務的人，都可能發動攻擊。儘速升級。升級前先套用緩解 1。
第 2 類
沒有啟用 APM 與 SSLO，管理介面已限制存取		管理介面的攻擊需要已登入的帳號。攻擊者要能連到管理介面，也要有帳號。安排在維護時段升級。升級前建議套用緩解 1。
第 3 類
沒有啟用 APM 與 SSLO，管理介面沒有限制存取		能連到管理介面、又有帳號或取得密碼的人，都可能發動攻擊。立即完成緩解 2，再儘速升級。

「管理介面已限制存取」要同時符合 3 個條件

  1. 管理埠只允許管理網段連線（httpd allow 清單或前端防火牆）。見緩解 2-1。
  2. 所有 Self IP 的 Port Lockdown 都不允許 TCP 443。Allow Default 包含 TCP 443。見緩解 2-2。
  3. 只有完全可信任的管理者有登入帳號。見緩解 2-3。

用下列唯讀指令確認：

# provisioned if the output shows "level ..."
tmsh list sys provision apm
tmsh list sys provision sslo
# management port allow list
tmsh list sys httpd allow
# check allow-service of each self IP
tmsh list net self

Self IP 的 allow-service 如果是 default、all，或清單中有 tcp:443，表示這個 Self IP 可以連到管理介面。

  • F5 在 2026-10-22 版的 K000163821 把 SSLO 與 APM 列在同一列，最新版只列 APM。本頁把 SSLO 歸到第 1 類。
  • 有啟用 APM，但沒有 virtual server 套用 Access profile 時，F5 沒有說明是否受影響。本頁歸到第 1 類。
第 2 類不代表沒有風險F5 對管理介面的評分仍是 High 7.5。請排定升級日期，不要無限期延後。

升級前

  1. 建立 UCS 備份，下載到電腦保存。
  2. 用 f5mku -K 查看 Master Key，和 UCS 一起保存。
  3. 在維護時段進行。啟用新版本時，設備會重新開機。

升級後

  1. 用 tmsh show sys version 確認版本。
  2. 用 rpm -q php --changelog | grep CVE-2026-109618 確認 PHP 已包含修正。應顯示 Fixed CVE-2026-109618 & CVE-2026-109619。
  3. 建議建立 /etc/php.ini.d/K000163878.ini，再重新啟動 Apache（見下方）。
  4. 繼續保留緩解 2 的管理介面存取限制。
掃描工具可能回報 PHP 5.4.45修正版的 PHP 版本仍顯示 5.4.45。F5 把修正 backport 到這個版本，版本號碼沒有改變。掃描工具可能依版本號碼回報漏洞，請以上面的 rpm 指令與 K000163821 為準。
升級後建議保留一項 PHP 設定修正版已修正 CVE-2026-109618／109619，緩解 1 的 4 項設定不需要重做。升級後，/etc/php.ini.d/ 下的檔案不會保留。F5 還在評估另一個 PHP 漏洞 CVE-2026-115560（K000163878）是否影響 BIG-IP，並建議把 session.upload_progress.enabled 設為 0。
cat > /etc/php.ini.d/K000163878.ini <<'EOF'
; The configuration mitigations recommended by PHP for CVE-2026-115560
; These will NOT survive an upgrade of BIG-IP TMOS.
session.upload_progress.enabled = 0
EOF
bigstart restart httpd
# APM systems only:
bigstart restart httpd_sam
升級步驟（含 GUI 畫面）

緩解 1　調整 BIG-IP 上的 PHP 設定（還沒升級的設備）

F5 建議套用 PHP 官方提供的設定緩解。請先在測試環境確認，再套用到正式設備。

1

以 root 登入 BIG-IP 的 bash（advanced shell）

2

建立 /etc/php.ini.d/K000163821.ini

cat > /etc/php.ini.d/K000163821.ini <<'EOF'
; The configuration mitigations recommended by PHP for CVE-2026-109618 and CVE-2026-109619
; These will NOT survive an upgrade of BIG-IP TMOS.
memory_limit = -1
post_max_size = 8M
upload_max_filesize = 7M
session.upload_progress.enabled = 0
EOF
3

重新啟動 Apache

bigstart restart httpd
# APM systems only:
bigstart restart httpd_sam

重新啟動期間 GUI 會短暫無法使用。重新啟動 httpd_sam 可能中斷 APM webtop 連線，使用者要重新連線。請在維護時段執行。

4

確認 PHP 已讀到新檔案

php -i | grep -E "Additional .ini|memory_limit|post_max_size|upload_max_filesize|session.upload_progress.enabled"

「Additional .ini files parsed」應包含 /etc/php.ini.d/K000163821.ini，4 個設定值應與上面的檔案相同。

參考：在 BIG-IP 17.5.1.8 上，套用前的值如下（以上述指令唯讀查得）：

設定17.5.1.8 原本的值F5 建議的值
memory_limit128M-1
post_max_size300M8M
upload_max_filesize300M7M
session.upload_progress.enabledOn0（Off）
注意 多 blade 的系統，每個 blade 都要做（使用 clsh bigstart restart httpd）。HA device group 中的每台設備都要做。升級 TMOS 後這個檔案不會保留。

緩解 2　限制管理介面的存取

F5 建議只讓可信任的使用者與設備，經由安全的網路連到管理介面。

2-1　管理埠：只允許可信任的來源 IP（K13309）

預設允許所有來源 IP（allow { All }）。用 tmsh 改成只允許管理網段：

tmsh list /sys httpd allow
tmsh modify /sys httpd allow replace-all-with { 192.0.2.0/255.255.255.0 }
tmsh save /sys config

範例中的 192.0.2.0/24 請換成實際的管理網段，可列多個。

小心不要把自己鎖在外面清單設錯時，GUI 會無法連線。請先從清單內的位址再開一個 SSH 連線備用。HA 對端設備、BIG-IQ、DCD 的位址也要加入清單（參考 K000160309）。
舊版本的限制BIG-IP 17.1.3.1、17.5.1.4 之前的版本，這份清單不會限制 port 443 上的 iControl REST。

2-2　Self IP：關閉 GUI 的存取（K17333）

Self IP 的 Port Lockdown 若設為 Allow Default，預設清單已包含 TCP 443（HTTPS），也就是可以從 Self IP 連到管理介面。請改成不含 TCP 443 的設定：

情況建議的 Port Lockdown
單機，或 HA 使用 hardwired failoverAllow None
HA 使用 network failoverAllow Custom，只開 UDP 1026
任何情況不要使用 Allow All
GUI 路徑Network ›› Self IPs ›› （Self IP 名稱）›› Port Lockdown ›› Update
tmsh list /net self
# no access to the self IP (ICMP is always allowed)
tmsh modify /net self <self_ip_name> allow-service none
# HA network failover only
tmsh modify /net self <self_ip_name> allow-service replace-all-with { udp:1026 }
tmsh save /sys config
  • HA 設備之間的 config sync（TCP 4353）與 mirroring 埠，不受 Port Lockdown 限制，會繼續運作。
  • 如果 DNS（GTM）的 iQuery 不是走 config sync 位址，要另外開放 TCP 4353。
  • 如果必須在 Self IP 開放 TCP 443，可用 BIG-IP 的 packet filter 限制來源網段（K13383）。
變更前確認Port Lockdown 會影響 Self IP 上的所有服務（例如 SNMP、SSH、DNS），HA 設定也可能受影響。請先確認這些服務是否經由 Self IP 使用（參考 K46122561）。

2-3　管理帳號

移除不是完全可信任的管理帳號，或降低其權限。管理介面的攻擊需要已登入的帳號。
